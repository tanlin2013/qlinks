# ICQMBS-to-Lindblad jump-bridge provisioning

**Updated:** 2026-08-15
**Status:** local/operator P0 implemented; independent Liouvillian P0.3 requires server run

## Scientific bridge now under test

For a reduced interference zero, reconstruct the directed kinetic caging row

\[
A_R=|z_R\rangle\langle v_R|,\qquad \langle v_R|P_{\mathcal T}=0.
\]

The direct open-system candidate retains the caging row and retargets only its output,

\[
J_R^{(\tau)}=|\tau_R\rangle\langle v_R|=M_{\tau z}A_R.
\]

This is the primary diagnostic bridge.  The generic modern `L`, selected multiplier `M`,
`ML`, final completion family, and deprecated single-state construction remain comparison
baselines rather than definitions of the bridge.

## Local/operator P0 status

`experimental/jobs/run_jump_bridge_p0.py` now exports, for the four 4x4 QDM targets:

- theorem-based attractive-subspace certificates for `A`, `A^dagger`, `Z`, `Y` where
  defined, `Q`, selected retargeted `A`, `L`, `M`, `ML`, and final families;
- state-resolved and full-target directed-caging action;
- state-level versus full-target shifted-potential `Y_R` action;
- reconstructable `A/Z/Y/L` provenance in `caging_to_lindblad_operator_map.jsonl`;
- local-annihilator/common-target basis-rotation checks;
- constrained-matrix-unit locality certificates;
- `M`/`ML` projection against the directed-`A` span;
- completion projection against the **unrestricted global left ideals** generated by
  directed `A_R` and by the selected modern `L_R` family.

The unrestricted-left-ideal test is stronger than the requested bounded-local projection
for exclusion: if a completion has nonzero residual even when arbitrary global left
multipliers are allowed, it cannot lie in any bounded-local caging-generated left ideal.

### Current lightweight findings

- Square single-state: the companion
  `Y_R=(F_{p1}-1)+(F_{p2}-1)` is state- and target-dark.
- Square 8D target: all 16 local companion `Y_R` candidates are dark on their originating
  state; their span contains a 9D common full-target-dark subspace.  Individual `Y_R`
  operators are not full-target dark.
- Honeycomb: the analogous two-plaquette shifted-potential candidate is not dark even on
  its originating caged eigenstate (residual about 1.225), so it is recorded as a rejected
  structural analogy rather than relabelled as a companion `Y_R`.
- Existing square and honeycomb single-target completion jumps have large nonzero residuals
  against even the unrestricted caging-generated left ideals.  They are therefore genuine
  completion operators rather than hidden `ML` elements.

A complete four-case local run is scientific/provisioning work rather than a unit test and
can take several minutes.  Run it on the server with:

```bash
QLINKS_EVIDENCE_RUN_ID=jump_bridge_p0 \
QLINKS_NUM_THREADS=8 \
QLINKS_DOCKER_MEMORY_LIMIT=64g \
scripts/docker_run_evidence_job.sh jump_bridge_p0 \
    --stage compute
```

The authoritative directory will be
`experimental/data/evidence_jobs/jump_bridge_p0_<timestamp>/`.

## P0.3 independent near-zero Liouvillian job

The independent spectrum job is
`experimental/jobs/run_jump_bridge_liouvillian.py`.  It rebuilds the same four targets and
checks `A_retargeted_single`, `ML`, and `final` against the theorem certificate.

The default `largest-real` ARPACK mode targets the Lindblad spectral boundary without
sparse-LU factorization.  A deliberately short local smoke test did not converge, so it
must not be treated as evidence; the server run should allow a much larger iteration
budget:

```bash
QLINKS_EVIDENCE_RUN_ID=jump_bridge_liouvillian_lr \
QLINKS_NUM_THREADS=8 \
QLINKS_DOCKER_MEMORY_LIMIT=64g \
scripts/docker_run_evidence_job.sh jump_bridge_liouvillian \
    --stage compute \
    --method largest-real \
    --maxiter 20000 \
    --eig-tolerance 1e-9 \
    --zero-tolerance 1e-8 \
    --peripheral-tolerance 1e-8
```

The default eigenpair budget is target-aware: at least the target-supported stationary
sector plus 16 external modes, capped at 96.  In particular, the square 8D target requests
80 modes so a putative 64-dimensional target-supported stationary sector does not exhaust
the returned spectrum.

If a case reports `solver_success=False` or insufficient converged modes, rerun only that
case/family with shift-invert on the server.  This fallback intentionally makes the
potential sparse-LU memory cost explicit:

```bash
QLINKS_EVIDENCE_RUN_ID=jump_bridge_liouvillian_si \
QLINKS_NUM_THREADS=8 \
QLINKS_DOCKER_MEMORY_LIMIT=128g \
scripts/docker_run_evidence_job.sh jump_bridge_liouvillian \
    --stage compute \
    --case square_qdm_4x4_single \
    --family A_retargeted_single \
    --method shift-invert \
    --sigma 1e-8 \
    --eig-tolerance 1e-10
```

Increase the container memory limit rather than changing the scientific tolerances if LU
fill-in is the limiting factor.

Authoritative spectrum outputs are:

- `liouvillian_near_zero.csv`: eigenvalues, zero/peripheral classification, and normalized
  eigenpair residuals;
- `liouvillian_summary.csv`: returned/expected mode counts, leading nonzero decay rate,
  theorem certificate, and consistency flag;
- `manifest.json`: exact CLI, solver parameters, thread environment, package versions, and
  git metadata.
